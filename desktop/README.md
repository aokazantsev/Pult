# Pult desktop

Программа в трее и хук-программа агента. Протокол 2: ключи P-256 в хранилище Windows, сопряжение по QR, сквозное
шифрование, вход «вызов — ответ» и подпись запросов — строго по [`protocol/CRYPTO.md`](../protocol/CRYPTO.md).

| Файл | Что делает |
|---|---|
| `Pult.exe` | трей: приём хуков на `127.0.0.1:<hook_port>`, сопряжение, поток SSE и подписанные `POST` к серверу-реле, режим «с телефона / с ПК» |
| `PultHook.exe` | хук-команда агента: событие из stdin → `Pult.exe`, ответ → stdout в UTF-8 |

Сборка — `build.cmd nostart` (оба exe, x64), тесты — `tests\run.cmd` (x64) и `tests\run.cmd x86`: логика, все
векторы `protocol/vectors/*.json` (ключи, сопряжение, конверт, вход), сопряжение, повтор и вход против фейкового
сервера протокола 2. Криптография — штатная .NET Framework 4.8 и CNG (`bcrypt.dll` для AES-GCM), без NuGet.

## Настройки

`%LOCALAPPDATA%\Pult\settings.txt` (создаётся при первом запуске, открывается из меню трея):

```
hook_port=47652
wait_seconds=300
server=https://example.com/pult
```

Порт хуков занимается исключительно (второй процесс на нём не сядет). Занят — `Pult.exe` повторяет привязку раз в секунду
до 6 минут (после перезапуска порт может быть занят остаточным состоянием TCP до ~4 минут), пункт меню трея показывает
«повторяю»; не освободился — «хуки не принимаются».

`wait_seconds` — ожидание Pult (10–540 с), меньше `timeout` хука. `server` — адрес сервера для нового сопряжения (его
же можно поправить в окне «Подключить телефон»). Пара этапа 1 (`pair`, `pc_token`) больше не читается: при первом
запуске она убирается из файла.

## Сопряжение

1. Меню трея → «Подключить телефон…». Окно проверяет сервер (`/info`, версия 2), создаёт ключи и заявку и показывает
   QR. Поле «Разорвать сессию после простоя» — срок простоя N (15 мин – 36 ч, по умолчанию 4 ч), он входит в QR.
2. QR действует 10 минут; за 20 с до срока окно само выпускает новый QR с новыми ключами («Новый QR» — то же вручную).
3. Телефон сканирует QR приложением Pult. ПК проверяет заверение ключей телефона секретом из QR, сохраняет их и
   показывает отпечаток из 16 цифр — сверьте его с экраном телефона. Не сошлось заверение — пара удаляется, окно
   предлагает новый QR.
4. «Разорвать» в меню трея удаляет пару на сервере и стирает ключи. Сессия кончается и сама: простой N без событий
   тредов, отвязка на телефоне, новое сопряжение, ПК без связи с сервером дольше 5 минут — причина приходит
   уведомлением в трее.

Закрыть окно до скана — заявка удаляется. Пока окно открыто, прежняя пара работает; успешное новое сопряжение рвёт её
(причина `replaced`).

## Данные

В `%LOCALAPPDATA%\Pult`:

| Файл | Что |
|---|---|
| `pair.txt` | сервер, `pair`, имена ключей ПК, открытые ключи телефона, срок простоя |
| `claim.txt` | заявка, ждущая скана; после перезапуска Pult секрета QR уже нет — заявка удаляется на сервере |
| `processed-<pair>.txt` | id обработанных сообщений телефона этой пары (последние 2000), переживают перезапуск |
| `hook-secret.txt`, `hook-log.txt`, `log.txt` | секрет хуков, отказы хука, журнал |

Закрытые ключи — в хранилище ключей пользователя Windows (Microsoft Software Key Storage Provider, имена
`Pult-<id>-sign`/`-agree`), неэкспортируемые; удаляются при разрыве пары.

## Хуки Claude Code

Проектный `.claude/settings.local.json` (или пользовательский `~/.claude/settings.json`), путь — к своей сборке:

```json
{
  "hooks": {
    "PermissionRequest": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 600 }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 600 }] }],
    "PostToolUse": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 10 }] }],
    "PostToolUseFailure": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 10 }] }],
    "StopFailure": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 10 }] }],
    "SessionStart": [{ "hooks": [{ "type": "command", "command": "\"D:/path/Pult/desktop/PultHook.exe\"", "timeout": 10 }] }]
  }
}
```

`PultHook.exe` сам отпускает агента через 570 с (`--limit <с>` меняет), это меньше `timeout` 600.

## Как работает

- Хук отправляет событие, только если порт держит `Pult.exe` из его же папки (владелец порта по таблице TCP), и
  прикладывает секрет `%LOCALAPPDATA%\Pult\hook-secret.txt`. Иначе — пустой ответ: агент показывает свой диалог.
  Отказы хука — `%LOCALAPPDATA%\Pult\hook-log.txt`.
- Нет пары, сервер или телефон несовместимы по версии — хуки сразу отпускают агента; причина — в меню трея и
  уведомлении.
- Вход: `/info` → вызов → подписанный `GET stream` → `stream` из первого события. Каждый `POST` подписан с потоком и
  счётчиком `n`; `401 stale_stream` — новый вход и повтор того же конверта, `409 replay` — повтор со следующим `n`.
  Конверты шифруются ключом направления ПК → телефон; от телефона принимаются только расшифровавшиеся конверты своей
  пары, остальные отбрасываются без подтверждения.
- При каждом подключении ПК шлёт `hello` (версии и возможности) и режим. `hello` телефона без версии 2 — «телефон
  несовместим»: запросы остаются в обычном диалоге на ПК. Сигнал сервера о чужой попытке входа — уведомление
  «От сервера: кто-то пытался войти в пару Pult», пара не рвётся.
- Решение с телефона хук подтверждает (`taken`); только после этого телефону уходит `answered`. Хук не взял решение
  (опоздал) — `expired`, связь с хуком оборвалась — `unknown`.
- `PermissionRequest` в режиме «с телефона» уходит на телефон и ждёт ответа, срока, переключения в «с ПК» или ответа
  на ПК: разрешение — `PostToolUse` того же треда, инструмента и `tool_input`; отказ — запись транскрипта
  (`toolDenialKind: user-rejected` или `[Request interrupted by user for tool use]`).
- `Stop` открывает окно текста, только если поток телефона открыт и продолжений подряд меньше предела
  (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, по умолчанию 8). Окно закрывают текст, срок, закрытие потока телефона, режим
  «с ПК» и запись `enqueue` в транскрипте (ввод на ПК или сообщение другого треда).
- Нет связи с сервером — запрос ждёт её в пределах срока (D-32) и уходит сразу после восстановления потока,
  переподключение — через 1, 2, 5 с; явный отказ сервера (4xx) — хук отпускается сразу. Повторная отправка не дублирует
  сообщение: идентификатор конверта задаётся один раз.
- Режим при запуске — «с телефона»; переключатель — в меню трея.
