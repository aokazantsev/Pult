## Итоги опытов с хуками (этап 1, шаг 2)

Claude Code 2.1.317 (desktop-приложение 4.23118.0), Windows 11, 06.11.2026. Опыты — в треде desktop-приложения
с хуками-заглушками `experiments/hooks` (режим разрешений «спрашивать») и в `claude -p` той же версии без входа:
без входа срабатывают только `SessionStart`, `UserPromptSubmit`, `StopFailure`, `SessionEnd`, поэтому разрешения,
окончание хода и родство проверены только в desktop-приложении, в CLI — по документации и схемам событий в коде
агента. F-2, F-8, F-10, F-11 в шаг не входили.

**HTTP-хук против скрипта.** HTTP-хук не поддерживается для `SessionStart` и `Setup` (агент пропускает его с
записью в журнале). Секрет в заголовке — только через `allowedEnvVars`, иначе пустая строка. По таймауту агент рвёт
соединение (сервер получает ошибку записи ответа), отказ соединения — ошибка без блокировки, ход идёт дальше.
Агент не проверяет, кто держит порт на loopback: процесс, занявший порт раньше фонового приложения (в том числе
другой учётной записи Windows), получает событие с секретом и может ответить сам. Условие §2 ARCHITECTURE («агент
сам убеждается, что адрес держит наше фоновое приложение») не выполнимо — выбран хук-скрипт.

**Затронутые решения.**
- §2, D-54 — HTTP-хук отпадает: хуки — скрипты, проверку фонового приложения делает скрипт.
- §5.3 п. 1–7, D-17, D-34, D-40 — в desktop-приложении диалог на ПК показан всё время ожидания хука и параллелен
  телефону: «стоит в диалоге на ПК» — с первой секунды, ответ на ПК может опередить телефон. Ответ на ПК desktop
  видит (`PostToolUse` — разрешение, запись транскрипта — отказ) и должен сам отпустить свой хук и закрыть запрос
  «решено на ПК»: агент хук не снимает. Что агент делает с ответом хука после ответа на ПК, не проверено.
- D-31, §5.3 «Ответ текстом» — ветка «desktop видит ввод на ПК»: признак — `enqueue` в транскрипте треда.
- §9 (F-15) — на 9-м подряд окне текста хук текст не берёт и отпускает ход сразу; либо desktop поднимает предел
  переменной `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`.
- §9 (F-19), D-58 — оркестратор не стоит до срока: `enqueue` сообщения дочернего треда — повод отпустить окно текста.
- D-59, §9 (F-17) — источник папки начала: `originCwd` desktop-приложения, `SessionStart` (`startup`), иначе
  каталог транскрипта; запасной вариант «папка первого события» не нужен.
- F-16 — статус «ошибка» от хука `StopFailure`, исключение D-47 не нужно.
