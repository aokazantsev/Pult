# Открытые факты платформы

| Факт | Как установить | Когда |
|---|---|---|
| F-1 | Хук PermissionRequest Claude Code может блокировать и вернуть allow/deny, а без решения отдать управление обычному диалогу | прототип хука | этап 1 |
| F-2 | PreToolUse на AskUserQuestion может подставить ответы через updatedInput | прототип хука | этап 3 |
| F-3 | Android Keystore: согласование ключей ECDH доступно с API 31 — определяет minSdk | документация, эмулятор | этап 2 |
| F-5 | Таймаут хука в Claude Code настраивается и выдерживает минуты ожидания | прототип хука | этап 1 |
| F-6 | Что делает Claude Code по истечении таймаута хука PermissionRequest: обычный диалог или отказ, убивается ли процесс хука | прототип хука | этап 1 |
| F-7 | Может ли desktop узнать исход обычного диалога агента на ПК (событие после решения) — нужно для `resolved: решён на ПК` | прототип хука | этап 1 |
| F-8 | Получает ли свёрнутое Android-приложение события по открытому потоку SSE и сколько живёт поток в фоне (Doze, экономия батареи производителя); решает, считается ли свёрнутое приложение «открытым» (§7) | эмулятор и телефон | этап 1 |
| F-9 | Хук окончания хода Claude Code может не дать ходу закончиться и передать агенту текст как продолжение; работает и в CLI, и в desktop-приложении; сколько минут хук может ждать | прототип хука | этап 1 |
| F-10 | Треды desktop-приложения пишут транскрипт так же, как CLI; насколько формат транскрипта стабилен между версиями | прототип, две версии Claude Code | этап 1 |
| F-11 | Где агент хранит название треда (заголовок в desktop-приложении): в транскрипте или отдельно | прототип | этап 1 |
| F-12 | Что происходит с вводом в поле агента на ПК, пока работает хук окончания хода: принимается ли, ставится ли в очередь, получает ли его агент после ответа хука, может ли desktop об этом узнать | прототип хука | этап 1 |
| F-13 | Сохраняется ли идентификатор треда (сессии агента) при возобновлении, форке и очистке контекста; пишет ли новый транскрипт прежнюю историю | прототип, CLI и desktop-приложение | этап 1 |
| F-14 | Откуда desktop узнаёт родителя дочернего треда и что дочерний тред ждёт пользователя: в событиях хуков Claude Code поля родителя нет; desktop-приложение хранит `spawnedFrom` в метаданных треда (недокументировано) | прототип | этап 1 |
| F-15 | Как ведёт себя ответ текстом при лимите Claude Code «8 продолжений хуком окончания хода подряд без вызова инструментов» | прототип хука | этап 1 |

Сверка с документацией и Claude Code 2.1.317 (06.11.2026): F-1, F-2, F-9 подтверждены; F-5 — таймаут хука 600 с по
умолчанию, поле `timeout`; F-10 — формат транскрипта документация называет внутренним, меняется между версиями; F-11 —
название в транскрипте (`custom-title`, `agent-name`) и в метаданных треда desktop-приложения; F-13 — `--resume`
сохраняет идентификатор, форк, `/branch` и `/clear` дают новый, метаданные desktop-приложения хранят прежние
идентификаторы и источник форка. Открытыми остаются F-6, F-8, F-12, F-13 (поведение), F-14, F-15.
