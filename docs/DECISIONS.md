# Замороженные решения

| ID | Решение |
|---|---|
| D-1 | Название Pult, пакет приложения ru.aokazantsev.pult |
| D-2 | Монорепозиторий MIT из четырёх блоков: protocol, desktop, server, mobile. Пятый блок push-gateway отложен (D-44) |
| D-3 | Без захвата экрана и имитации кликов; управление только через хуки агента |
| D-4 | Без веб-панели и учётных записей; сопряжение ПК и телефона по QR |
| D-5 | Ключи P-256 (ECDSA + ECDH), закрытые ключи не покидают устройство, сервер хранит только открытые |
| D-6 | Сквозное шифрование: сервер — реле, содержимого не видит |
| D-7 | Мобильное приложение KMP + Compose Multiplatform; iOS собирается, но не отлаживается и не публикуется |
| D-9 | Сервер разворачивается кем угодно; mobile официально только наш |
| D-11 | Адрес сервера задаётся при установке desktop и передаётся телефону через QR |
| D-12 | Свободный ввод текста в тред — в MVP. Механизм — ответ в конце хода: хук окончания хода агента ждёт текст с телефона и возвращает его агенту как продолжение. Прерывание агента посреди хода и создание нового треда с телефона не делаются — ограничение принято владельцем |
| D-13 | QR несёт одноразовый секрет сопряжения, который сервер никогда не получает; серверу уходит только идентификатор заявки. Телефон подтверждает свои ключи этим секретом, ПК проверяет. Сверка отпечатка — дополнительная защита |
| D-14 | Неверная попытка сопряжения сжигает заявку; ПК сообщает о попытке и предлагает новый QR |
| D-15 | Чужие попытки входа в пару и нерасшифровавшиеся сообщения пару не разрывают: сервер ограничивает частоту, сообщение отбрасывается, пользователь получает уведомление |
| D-16 | Сессия = пара. Рвётся с обеих сторон только по одному из поводов: N без событий тредов сессии (D-22, D-23, D-33); кнопка «Разорвать» на ПК; отвязка с телефона. Закрытие последнего треда сессию не рвёт: пользователь может готовить следующий тред, отсчёт простоя идёт от последнего события. Пользователю показывается причина разрыва. Новая сессия — новый QR и новые ключи |
| D-17 | Куда идут запросы, решает переключатель в окне desktop (как у DevMonitor): «управление с телефона» / «управление с ПК». Режим ПК — хуки сразу отдают решение обычному диалогу. Переключение в режим ПК отпускает ждущие запросы в обычный диалог, телефону уходит «решено на ПК». Переключатель только на ПК, телефон режим видит, но не меняет. Детектора простоя нет |
| D-18 | Строго 1 ПК ↔ 1 телефон. Новое сопряжение на любой стороне заменяет прежнюю сессию этой стороны. Несколько ПК на телефоне и несколько серверов на телефоне не поддерживаются |
| D-19 | Вход в приложение на телефоне — по биометрии или PIN; отдельного подтверждения на каждый ответ нет. В окне desktop — кнопка «Разорвать» |
| D-20 | Удалённого отзыва нет: отвязка — с ПК или телефона; потерянный телефон ограничен сроком сессии (D-16) и биометрией (D-19) |
| D-21 | Отвязка с телефона без связи допустима: ПК может считать сессию живой, пока пользователь не нажмёт «Разорвать» на ПК или не истечёт срок простоя. Последствие принято: в режиме «управление с телефона» каждый запрос ждёт до срока хука и уходит в обычный диалог ПК. Записывается в ограничения, нового механизма нет |
| D-22 | Срок простоя N настраивается в desktop перед показом QR и передаётся телефону в QR; по умолчанию 4 часа, от 15 минут до 36 часов. Срок фиксирован на всю сессию, телефон его не меняет. Отсчёт ведёт только ПК по событиям агента (D-23); по истечении ПК рвёт сессию, телефон узнаёт об этом при следующем подключении |
| D-23 | Действия на телефоне простой не продлевают. Простой считается только по событиям агента на ПК: ответ с телефона двигает агента, и уже его хуки дают события. Телефон без ответов N часов на блокирующем запросе — событий нет, сессия рвётся |
| D-24 | Новое сопряжение рвёт прежнюю сессию в момент успешного сопряжения новой; отдельного события «заменена» нет — обычный разрыв старой и начало новой |
| D-25 | Кто первым отсканировал QR, тот и создал сессию. После сопряжения QR на ПК исчезает, ПК показывает сессию и кнопку «Разорвать». Отдельного сигнала о перехвате нет |
| D-26 | Desktop потерял соединение с сервером по любой причине (сон, сеть, перезапуск, падение) — 5 минут попыток восстановить. Восстановил — сессия продолжается. Не восстановил — сессия разорвана с обеих сторон: ПК считает её разорванной сам, сервер удаляет пару через 5 минут без ПК, телефон узнаёт при подключении. Ответственность за доступность ПК — на пользователе |
| D-28 | Новая сессия стартует в режиме «управление с телефона». При восстановлении связи в пределах 5 минут (D-26) режим сохраняется |
| D-29 | Телефон показывает полную ленту треда: промежуточные и итоговые сообщения агента, вызовы инструментов (вывод обрезается), сообщения пользователя, запросы и вопросы. Источник — транскрипт треда, который desktop читает по мере записи; адаптер агента приводит его к общему виду. Всё рисуется одной карточкой общего формата с необязательными действиями. Ход рассуждений модели не показывается |
| D-30 | В сессию входят треды, выбранные при показе QR из последних N по активности (по умолчанию 5, отмечены все), и все треды, созданные после сопряжения. Тред появляется на телефоне с первого своего события после сопряжения; история до сопряжения не передаётся, молчащий тред остаётся только на ПК. Треды вне сессии Pult не трогает: их хуки сразу отдают решение обычному диалогу. На телефоне — список тредов в навбаре со статусом и отметкой «ждёт действия». Название треда — из данных агента, иначе первое сообщение пользователя и папка проекта |
| D-31 | Ввод на ПК, пока хук окончания хода ждёт текст с телефона: если desktop получает сигнал о вводе на ПК (F-12) — ввод на ПК побеждает, хук отпускается, текст с телефона отвергается; если сигнала нет — ограничение: в режиме «с телефона» сначала переключить режим. Выбор фиксируется по итогу этапа 1 |
| D-32 | Запрос, пришедший во время восстановления связи desktop с сервером (D-26), ждёт восстановления в пределах срока хука, затем уходит на телефон |
| D-33 | Простой N продлевают только события тредов сессии (D-30), в любом режиме |
| D-34 | Отметка «ждёт действия» — только у запросов разрешения и вопросов; конец хода с ожиданием текста отмечается «ждёт текста» (D-41) |
| D-35 | Тред с новым идентификатором после продолжения, форка или очистки контекста входит в сессию, только если его исходный тред в сессии; в ленту — только записи после сопряжения (родство — F-13) |
| D-36 | Ожидание текста в конце хода — тот же срок, что у запроса. Ограничение: без открытого приложения окно обычно пропускается. Тред на телефоне показывает «ждёт текста» на время окна и «окно закрыто» после. Отдельный длинный срок — после проверки F-9 на этапе 1 |
| D-37 | Продолжение треда (тот же разговор, новый идентификатор) — та же лента и тот же пункт списка. Форк — отдельный пункт с пометкой «форк …». Родство не определилось (F-13) — тред считается не входящим в сессию и остаётся на ПК |
| D-39 | О чужих попытках входа сервер шлёт служебный сигнал без текста; приложение и desktop показывают фиксированную фразу с пометкой «от сервера» |
| D-40 | Обрыв канала или пропажа хука после передачи ему решения — итог «неизвестен», не «истёк»: действие могло выполниться |
| D-41 | Окно ожидания текста видно в списке тредов отдельной отметкой «ждёт текста», отличной от «ждёт действия» (D-34) |
| D-42 | Сервер, отвергнув `hello` телефона по версии, шлёт ПК служебный сигнал «телефон несовместим»; ПК показывает его, хуки сразу отдают решение обычному диалогу |
| D-43 | После долгого отсутствия связи снимок дополняет имеющуюся ленту треда; на стыке пометка «пропущены записи» |
| D-44 | Пуши при закрытом приложении и публикация в RuStore отложены на неопределённый срок (06.11.2026). Уведомлений нет совсем — ни пушей, ни системных, ни звука: пользователь сам наблюдает за тредами в открытом приложении. Распространение — APK в GitHub Releases. Идеи сохранены: §11 ARCHITECTURE.md и раздел ниже |
| D-45 | Транспорт — HTTPS: события от сервера потоком SSE, свои сообщения — подписанные `POST`; одна схема для ПК и телефона. WebSocket заменён (06.11.2026) |
| D-46 | Дочерний тред (запущен другим тредом) входит в сессию, только если в ней родитель; на телефоне — под родителем, у родителя сводная отметка ожидания. Сообщения между тредами — в ленте обоих. Родитель не определился — тред самостоятельный (06.11.2026) |
| D-47 | Нераспознанная запись транскрипта пропускается с пометкой в ленте; статусы и запросы идут от хуков и от формата транскрипта не зависят (06.11.2026) |
