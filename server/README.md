# Pult server

Реле между ПК и телефоном: поток SSE и `POST` для обеих сторон, очередь на получателя на диске, служебный сигнал
«поток телефона открыт / закрыт» для ПК, порог живости. Python 3.10+, только стандартная библиотека. Формат сообщений —
[`protocol/README.md`](../protocol/README.md).

## Запуск

```bash
python3 -m pult_relay add-pair --id dev
python3 -m pult_relay run
```

`add-pair` печатает токены ПК и телефона и записывает их в `data/pairs.json`; `remove-pair <id>` удаляет пару с её очередью. Windows —
`run.cmd`, Linux — `run.sh`.

- Пары меняют при остановленном сервисе: работающий процесс держит пары и очереди в памяти, читает `pairs.json` только при
  старте и затирает чужую правку при следующей записи состояния.
- Без пар `run` создаёт пару сам и печатает её токены в стандартный вывод (в журнал сервиса): после первого запуска
  журнал с токенами прибрать.
- Битый `pairs.json` или `state.json` при старте переименовывается в `*.corrupt`, сервер стартует с пустым файлом (для
  `pairs.json` — без пар, то есть `run` заведёт новую пару); разобрать `*.corrupt` вручную.

| Переменная | По умолчанию | |
|---|---|---|
| `PULT_DATA` | `data` | каталог состояния (`pairs.json`, `state.json`) |
| `PULT_HOST`, `PULT_PORT` | `127.0.0.1`, `8082` | адрес |
| `PULT_MAX_TTL` | `900` | верхняя граница срока жизни конверта, с |
| `PULT_MAX_QUEUE` | `200` | очередь на получателя, сообщений |
| `PULT_MAX_QUEUE_BYTES` | `4194304` | очередь на получателя, суммарный размер конвертов, байт |
| `PULT_MAX_ENVELOPE` | `65536` | размер конверта, байт |
| `PULT_KEEPALIVE`, `PULT_LIVENESS` | `15`, `45` | комментарий в потоке; порог «без признаков жизни», с |

Состояние пишется атомарно (временный файл, `fsync`, `os.replace`) при каждом изменении очереди и переживает перезапуск.
Отказы `POST`: `401` — токен неверный (в том числе не из ASCII), `411` — нет ни `Content-Length`, ни chunked, `413` —
тело больше `PULT_MAX_ENVELOPE` (chunked-тело считается по тому же пределу), `429` — очередь получателя длиннее
`PULT_MAX_QUEUE`, `507` — суммарный размер очереди получателя превысил бы `PULT_MAX_QUEUE_BYTES`. Очередь живёт в памяти
и в `state.json`, поэтому предел размера держит и память после перезапуска; освобождается подтверждением (`acks`) или сроком
жизни конверта.

После перезапуска все потоки закрыты, клиенты переподключаются сами.

## Тесты

```bash
python3 -m unittest discover -s tests -t .
```

Включая перезапуск процесса: очередь и память идентификаторов целы.
